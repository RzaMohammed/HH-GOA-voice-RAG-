## 1. Executive Summary

This project implements an end-to-end, production-ready, low-latency **Voice-First Multilingual RAG System** specialized for Indic and English information retrieval. The system is designed to allow users to either speak or type questions in multiple languages (Hindi, English, Bengali, Tamil, Telugu, Marathi, Gujarati, etc.), retrieve verified context passages using a parallel hybrid search (FAISS Dense + BM25 Lexical), rerank candidates using a Cross-Encoder, generate grounded answers with passage citations via Sarvam AI, verify factual claims against context to prevent hallucinations, and synthesize spoken responses back to the user in real time.

## 3. Detailed Step-by-Step RAG Pipeline Flow

Here is exactly how a user query traverses the RAG pipeline from start to finish at the current stage:

```
[User Audio / Text Input]
           │
           ▼
┌────────────────────────────────────────────────────────┐
│ Stage 1: Audio Input & Speech-to-Text (STT)           │
│  - Detects audio mime type (WAV, WebM, MP3, OGG)       │
│  - Calls Sarvam AI STT (`saaras:v2` / `translate`)     │
│  - Fallback: ElevenLabs STT -> Client transcript      │
└──────────────────────────┬─────────────────────────────┘
                           │ Query Text + Detected Language
                           ▼
┌────────────────────────────────────────────────────────┐
│ Stage 2: Pre-Retrieval Guardrails                      │
│  - Safety: Scans for prompt injection & harmful inputs │
│  - Relevance: Checks domain relevance & off-topic patterns
│  - If FAIL -> Immediate safe refusal (REFUSAL_SAFETY)  │
└──────────────────────────┬─────────────────────────────┘
                           │ Validated Query
                           ▼
┌────────────────────────────────────────────────────────┐
│ Stage 3 & 4: Parallel Hybrid Retrieval                 │
│  ├─ Dense Vector Search: FAISS Inner Product Search     │
│  │   • Query embedded via Fine-Tuned Multilingual BERT │
│  │   • Query embedding cached in Thread-safe LRU Cache │
│  │   • Returns Top-50 cosine similarity matches       │
│  └─ Lexical Search: BM25Okapi                          │
│      • Indic-aware tokenization & preprocessing        │
│      • Returns Top-50 keyword matches                  │
│  (Both branches run concurrently via asyncio.gather)   │
└──────────────────────────┬─────────────────────────────┘
                           │ Dense & Lexical Candidates
                           ▼
┌────────────────────────────────────────────────────────┐
│ Stage 5: Hybrid Score Fusion                           │
│  - Reciprocal Rank Fusion (RRF, k=60):                 │
│      Score = Σ 1 / (60 + rank_i)                       │
│  - OR Convex Weighted Fusion:                          │
│      Score = α * norm(dense) + (1-α) * norm(bm25)      │
└──────────────────────────┬─────────────────────────────┘
                           │ Top Candidate Pool (30-50 chunks)
                           ▼
┌────────────────────────────────────────────────────────┐
│ Stage 6: Cross-Encoder Reranking                       │
│  - Model: cross-encoder/ms-marco-MiniLM-L-6-v2         │
│  - Evaluates cross-attention pairs (Query, Passage_i)  │
│  - Sorts by deep semantic relevance score              │
│  - Selects Top-K (default: 5) most relevant passages   │
└──────────────────────────┬─────────────────────────────┘
                           │ Top-5 Reranked Chunks
                           ▼
┌────────────────────────────────────────────────────────┐
│ Stage 7: Confidence Gating Guardrail                   │
│  - Validates top score >= min_retrieval_score (0.25)   │
│  - If evidence is too weak -> REFUSAL_NO_EVIDENCE      │
└──────────────────────────┬─────────────────────────────┘
                           │ High-Confidence Context Passages
                           ▼
┌────────────────────────────────────────────────────────┐
│ Stage 8: Grounded LLM Generation                       │
│  - Provider: Sarvam AI (sarvam-105b / sarvam-2b)       │
│  - System Prompt: Strict factual grounding constraint   │
│  - Formats context into numbered [Passage 1..N] tags  │
│  - Fallback: Deterministic Extractive QA (MockLLM)     │
└──────────────────────────┬─────────────────────────────┘
                           │ Generated Candidate Answer
                           ▼
┌────────────────────────────────────────────────────────┐
│ Stage 9: Post-Generation Grounding Verification        │
│  - Deconstructs answer into individual factual claims  │
│  - Computes n-gram / word overlap against context      │
│  - Status: GROUNDED (>=80%), PARTIAL (>=40%), UNGROUNDED
│  - If UNGROUNDED -> Replaces answer with refusal       │
└──────────────────────────┬─────────────────────────────┘
                           │ Grounded Verified Answer
                           ▼
┌────────────────────────────────────────────────────────┐
│ Stage 10: Voice Synthesis (TTS) [Optional / Auto]     │
│  - Language-aware voice routing                        │
│  - Sarvam Bulbul TTS (hi-IN, bn-IN, ta-IN, etc.)       │
│  - ElevenLabs Multilingual v2 (en, global voices)      │
│  - Returns Base64 audio stream to frontend             │
└──────────────────────────┬─────────────────────────────┘
                           │
                           ▼
[Final Response: Text Answer + Source Passages + Audio + Per-Stage Latency Trace]
```

## 4. Deep Dive into Pipeline Components

### 4.1 Document Ingestion & Chunking (`voice_rag/indexing/chunkers.py`)
Four chunking strategies are supported and can be configured dynamically:
1. **Fixed Word-Window:** Chunks text into fixed word sizes (default: 120 words) with configurable overlap (default: 25 words).
2. **Sentence-Aware:** Splits on punctuation respecting both English (`.`, `!`, `?`) and Indic danda characters (`।`, `॥`), aggregating whole sentences without breaking meaning.
3. **Semantic Chunking:** Computes consecutive sentence embedding cosine similarity; inserts boundaries wherever semantic similarity dips below a threshold (default: 0.65).
4. **Adaptive Chunking (Default):** Heuristically uses sentence-aware chunking for concise texts (≤ 300 words) and automatically escalates to semantic chunking for longer documents.

### 4.2 Embedding & FAISS Indexing (`voice_rag/indexing/embeddings.py`, `build_faiss.py`)
- **Model:** Fine-tuned multilingual embedder (`result/finetuned_multilingual_embedder/` based on BERT/sentence-transformers, 384-dimensional vector space).
- **Index Type:** `faiss.IndexFlatIP` (Exact Inner Product Search). Because all vectors are L2-normalized during embedding, inner product is mathematically identical to cosine similarity. Support for `HNSWFlat` and `IVFFlat` is also built-in for scaling.
- **LRU Vector Caching:** `LRUQueryVectorCache` caches frequently queried query vectors in memory to eliminate redundant neural network forward passes for repeated queries.

### 4.3 BM25 Lexical Retrieval (`voice_rag/retrieval/lexical.py`, `build_bm25.py`)
- Uses `rank_bm25.BM25Okapi`.
- Queries and passages are preprocessed and tokenized using an Indic-aware Unicode tokenizer (`voice_rag/data/preprocessing.py`).
- Persists both index binaries (`bm25_index.pkl`) and chunk metadata (`bm25_chunks.json`).

### 4.4 Hybrid Fusion & Reranking (`voice_rag/retrieval/hybrid.py`, `reranker.py`)
- **Parallel Retrieval:** Dense FAISS search and BM25 lexical search are launched simultaneously using `asyncio.get_running_loop().run_in_executor()` and merged with `asyncio.gather()`.
- **Fusion Method:** Default is **Reciprocal Rank Fusion (RRF)** with standard $k=60$. Alternatively, **Convex Score Fusion** normalizes both score spaces via min-max normalization and applies a tunable weight $\alpha = 0.6$ for dense and $(1-\alpha) = 0.4$ for lexical.
- **Cross-Encoder Reranking:** Top 30–50 fused candidates are processed with `cross-encoder/ms-marco-MiniLM-L-6-v2` in batch mode, generating a precision-ranked Top-5 candidate list.

### 4.5 LLM Generation & Grounding Guardrails (`voice_rag/generation/`, `guardrails/`)
- **Primary LLM:** Sarvam AI `sarvam-105b` (or `sarvam-2b`) using the official SDK with automatic fallback to REST completions.
- **System Prompt:** Enforces strict adherence to context and citations (`[Passage 1]`, `[Passage 2]`).
- **Grounding Verifier (`grounding.py`):** Automatically breaks down generated responses into factual claim clauses, computes n-gram and word overlap against retrieved context passages, and classifies the response into `GROUNDED`, `PARTIALLY_GROUNDED`, or `UNGROUNDED`. Ungrounded responses are refused automatically to prevent hallucinations.
- **Confidence Gate (`confidence.py`):** If the top retrieved chunk score is below `0.25`, the pipeline skips LLM generation entirely and returns `REFUSAL_NO_EVIDENCE`.

### 4.6 Voice Module: STT & TTS (`voice_rag/voice/`)
- **Sarvam AI STT:** Audio bytes are analyzed via magic bytes (WAV, WebM, MP3, OGG) and sent to Sarvam's `speech-to-text` or `speech-to-text-translate` API with targeted Indic language codes (`hi-IN`, `bn-IN`, `ta-IN`, `te-IN`, `mr-IN`, `gu-IN`, etc.).
- **ElevenLabs STT:** Secondary STT provider fallback.
- **Sarvam AI TTS:** Synthesizes responses using Sarvam's `bulbul:v1` engine (speaker: `meera`) for natural Indian accent pronunciation.
- **ElevenLabs TTS:** High-fidelity multilingual TTS using model `eleven_multilingual_v2` (voice: `Rachel`).

## 6. End-to-End Latency Tracking & Telemetry

Every request through `RAGOrchestrator.process()` populates a structured `LatencyTrace` object capturing micro-timing:
- `stt`: Speech-to-text conversion time
- `guardrail_safety`: Injection & harmful check time (~0.1 ms)
- `guardrail_relevance`: Intent and domain check time (~0.1 ms)
- `retrieval`: Parallel FAISS + BM25 search time (~1.5–5 ms)
- `fusion`: RRF / Weighted fusion time (~0.2 ms)
- `reranking`: Cross-encoder inference time (~15–40 ms on GPU / ~80–150 ms on CPU)
- `guardrail_confidence`: Score gating time (~0.1 ms)
- `generation`: LLM response streaming / completion time (~250–800 ms)
- `grounding`: Factual claim verification time (~0.5–2 ms)
- `tts`: Voice synthesis time (~300–600 ms)
- `total_ms`: Total end-to-end latency

The frontend renders this telemetry breakdown in a visual pipeline timeline for every query.

## 8. Summary of Strengths & Next Opportunities

### Key Strengths:
1. **True Multilingual Support:** Optimized for Indian languages with Sarvam AI, Indic sentence splitting, and a fine-tuned multilingual embedder.
2. **Parallel Hybrid Search:** Dense semantic search and BM25 keyword search run concurrently, joined by RRF to combine strengths.
3. **Layered Guardrails:** Pre-retrieval safety/relevance, retrieval confidence gating, and post-generation grounding checks eliminate hallucinations and protect system integrity.
4. **Voice-First Experience:** Seamless audio recording, STT transcription, RAG retrieval, grounded answer generation, and TTS voice playback over REST and WebSockets.

### Next Steps / Expansion:
- Scale knowledge corpus ingestion to millions of passages using `build_knowledge_base.py` / `download.py` with streaming Parquet loading.
- Enable FAISS `HNSWFlat` or `IVFFlat` index modes when scaling corpus size above 100k chunks.
- Explore quantized on-device STT/TTS models (e.g. Whisper / VITS) for local offline edge deployment.
